# راهنمای بارگذاری مسئله «پازل» در پنل مدیریت سامانه داوری

این راهنما برای کسی نوشته شده که فقط به پنل وب مدیریت سامانه داوری دسترسی دارد و هیچ دسترسی به سرور یا خط فرمان آن ندارد. همه فایل‌های لازم در پوشه زیر آماده شده‌اند:

```
jigsaw/cms_upload/
```

نام سامانه داوری و نسخه‌ای که این راهنما برای آن نوشته شده:

```
CMS 1.4 / CMS 1.5  (Admin Web Server)
```

## نکته بسیار مهم پیش از شروع

این مسئله **تعاملی** است. یعنی برنامه شرکت‌کننده با یک برنامه داور به نام «مدیر» گفتگو می‌کند. بنابراین نوع مسئله نباید «دسته‌ای» باشد و باید نوع زیر انتخاب شود:

```
Communication
```

به همین دلیل در این مسئله فایل بررسی‌کننده خروجی وجود ندارد و به‌جای آن یک فایل اجرایی به نام زیر بارگذاری می‌شود که هم با برنامه شرکت‌کننده گفتگو می‌کند و هم امتیاز را حساب می‌کند:

```
manager
```

فهرست فایل‌های داخل پوشه بارگذاری:

```
statement.pdf                      صورت مسئله
tests.zip                          همه ورودی‌ها و خروجی‌ها (۶۴ آزمون)
manager                            فایل اجرایی ایستا برای لینوکس ۶۴ بیتی
manager.cpp                        کد منبع همان فایل (فقط برای مرجع؛ بارگذاری نشود)
attachments/sample.in              داده نمونه برای شرکت‌کنندگان
attachments/local_interactor.cpp   داور محلی برای آزمایش شرکت‌کنندگان
score_type.txt                     پارامترهای دقیق نوع امتیازدهی
task_settings.txt                  خلاصه همه مقادیر پنل
```

---

## ۱. ساختن مسئله

۱. وارد پنل مدیریت شوید. در منوی سمت چپ، در بخش مسئله‌ها، روی پیوند زیر کلیک کنید:

```
Create new task...
```

۲. در فیلد زیر:

```
Name
```

این مقدار را بنویسید:

```
jigsaw
```

۳. در فیلد زیر:

```
Title
```

این مقدار را بنویسید:

```
Jigsaw Puzzle
```

۴. روی دکمه زیر کلیک کنید تا مسئله ساخته شود و صفحه آن باز شود:

```
Create
```

۵. در همان صفحه مسئله، در صورت وجود این فیلدها، مقادیر زیر را تنظیم کنید و در پایان صفحه دکمه ذخیره را بزنید.

حالت امتیاز (سبک المپیاد جهانی: بیشترین امتیاز هر زیرمسئله در میان همه ارسال‌ها):

```
Score mode:  Use the best score among all submissions, per subtask   (max_subtask)
```

سطح بازخورد در نسخه ۱.۵:

```
Feedback level:  Full
```

دقت امتیاز:

```
Score precision:  0
```

حالت ژتون‌ها:

```
Token mode:  Tokens disabled
```

دکمه ذخیره:

```
Update
```

## ۲. بارگذاری صورت مسئله

۱. در صفحه مسئله، به بخش صورت‌ها بروید و روی پیوند زیر کلیک کنید:

```
Add statement
```

۲. در فیلد کد زبان این مقدار را بنویسید:

```
Language code:  en
```

۳. در فیلد فایل، این فایل را انتخاب کنید:

```
cms_upload/statement.pdf
```

۴. دکمه زیر را بزنید:

```
Add statement
```

۵. اگر مسابقه چند زبانه نیست، می‌توانید در صفحه مسئله این زبان را به‌عنوان زبان اصلی صورت در فیلد زیر انتخاب کنید:

```
Primary statements
```

## ۳. بارگذاری پیوست‌ها

۱. در صفحه مسئله، در بخش پیوست‌ها روی پیوند زیر کلیک کنید:

```
Add attachment
```

۲. فایل اول را انتخاب و بارگذاری کنید:

```
cms_upload/attachments/sample.in
```

۳. همین کار را برای فایل دوم تکرار کنید:

```
cms_upload/attachments/local_interactor.cpp
```

نام فایل‌ها در پنل همان نام اصلی باقی بماند.

## ۴. تنظیم مجموعه داده

در پایین صفحه مسئله بخشی برای مجموعه داده‌ها هست. به‌طور پیش‌فرض یک مجموعه داده فعال با نام زیر ساخته شده است:

```
Default
```

روی آن کلیک کنید تا صفحه تنظیمات آن باز شود (در بعضی نسخه‌ها تنظیمات مستقیماً در همان صفحه مسئله نمایش داده می‌شود).

### محدودیت زمان

در فیلد زیر:

```
Time limit
```

این مقدار را بنویسید (واحد ثانیه است):

```
2
```

### محدودیت حافظه

در فیلد زیر:

```
Memory limit
```

این مقدار را بنویسید (واحد مگابایت است، نه بایت):

```
256
```

### نوع مسئله

در فهرست کشویی زیر:

```
Task type
```

این گزینه را انتخاب کنید:

```
Communication
```

پس از انتخاب، چند فیلد تازه ظاهر می‌شود. آن‌ها را این‌گونه پر کنید.

تعداد فرایندهای کاربر:

```
Number of user processes:  1
```

نحوه ترجمه برنامه (برنامه شرکت‌کننده به تنهایی ترجمه شود):

```
Compilation:  Submissions are self-sufficient      (alone)
```

نحوه ورودی و خروجی (ورودی و خروجی استاندارد):

```
User I/O:  Using standard input and output        (std_io)
```

### نوع امتیازدهی

در فهرست کشویی زیر:

```
Score type
```

این گزینه را انتخاب کنید:

```
GroupMin
```

در جعبه متن پارامترها:

```
Score type parameters
```

دقیقاً متن زیر را جای‌گذاری کنید (همین متن در فایل امتیازدهی هم هست):

```
[[0, "^00-[0-9]+$"], [10, "^01-[0-9]+$"], [15, "^02-[0-9]+$"], [20, "^03-[0-9]+$"], [25, "^04-[0-9]+$"], [30, "^0[0145]-[0-9]+$"]]
```

معنی گروه‌ها:

```
گروه ۰ :  ۰ امتیاز   ^00-   مثال صورت مسئله                 ۱ آزمون
گروه ۱ : ۱۰ امتیاز   ^01-   n <= 3 , q = n-1                ۴ آزمون
گروه ۲ : ۱۵ امتیاز   ^02-   q = 2n                          ۱۲ آزمون
گروه ۳ : ۲۰ امتیاز   ^03-   q = n                           ۱۲ آزمون
گروه ۴ : ۲۵ امتیاز   ^04-   n odd , q = n-1                 ۱۳ آزمون
گروه ۵ : ۳۰ امتیاز   ^0[0145]-   q = n-1 (کامل)             ۴۰ آزمون
```

گروه پنجم علاوه بر آزمون‌های خودش، آزمون‌های گروه‌های صفر، یک و چهار را هم شامل می‌شود؛ این کار عمدی است.

در پایان دکمه ذخیره را بزنید:

```
Update
```

## ۵. بارگذاری فایل مدیر

در این مسئله به‌جای بررسی‌کننده، فایل مدیر بارگذاری می‌شود.

۱. در صفحه مجموعه داده، در بخش فایل‌های مدیریتی روی پیوند زیر کلیک کنید:

```
Add manager
```

۲. این فایل را انتخاب کنید:

```
cms_upload/manager
```

۳. نام فایل در پنل باید **دقیقاً** این باشد؛ بدون پسوند، با حروف کوچک:

```
manager
```

اگر مرورگر یا سیستم‌عامل شما نام فایل را تغییر داده است (مثلاً پسوند اضافه کرده)، پیش از بارگذاری نام را اصلاح کنید.

۴. دکمه زیر را بزنید:

```
Add manager
```

۵. در این مسئله گزینه‌ای برای مقایسه خروجی وجود ندارد و هیچ بررسی‌کننده‌ای نباید بارگذاری شود. فایل زیر را هم بارگذاری **نکنید**؛ فقط برای مرجع است:

```
manager.cpp
```

این فایل اجرایی به‌صورت ایستا ساخته شده است و به هیچ کتابخانه‌ای روی سرور نیاز ندارد. دستور ساخت آن برای مرجع:

```
g++ -O2 -static -std=gnu++17 -o manager manager.cpp
```

## ۶. بارگذاری گروهی آزمون‌ها

۱. در صفحه مجموعه داده، در بخش آزمون‌ها روی پیوند زیر کلیک کنید:

```
Add multiple testcases
```

۲. در فیلد فایل، این فایل را انتخاب کنید:

```
cms_upload/tests.zip
```

۳. الگوی نام ورودی را دقیقاً این‌گونه بنویسید:

```
Input template:  *.in
```

۴. الگوی نام خروجی را دقیقاً این‌گونه بنویسید:

```
Output template:  *.out
```

۵. گزینه عمومی بودن آزمون‌ها را **علامت بزنید** تا شرکت‌کننده امتیاز هر زیرمسئله را ببیند (سبک المپیاد جهانی):

```
Public
```

اگر این گزینه را نزنید، شرکت‌کننده فقط امتیاز آزمون‌های عمومی را می‌بیند و همیشه صفر خواهد دید. اگر عمداً بازخورد محدود می‌خواهید، فقط آزمون زیر را عمومی کنید:

```
00-01
```

۶. گزینه بازنویسی فقط هنگام بارگذاری دوباره لازم است:

```
Overwrite
```

۷. دکمه زیر را بزنید:

```
Add
```

۸. پس از بارگذاری، تعداد آزمون‌ها را در فهرست آزمون‌ها بشمارید. باید دقیقاً این تعداد باشد:

```
64
```

و نام‌ها باید این بازه‌ها را پوشش دهند:

```
00-01
01-01 ... 01-04
02-01 ... 02-12
03-01 ... 03-12
04-01 ... 04-13
05-01 ... 05-22
```

نام هر آزمون از دو بخش تشکیل شده است: شماره زیرمسئله و شماره آزمون. برای نمونه نام زیر یعنی آزمون سوم از زیرمسئله یک:

```
01-03
```

پرونده خروجی هر آزمون، جایگشت مخفی هر مورد آزمون را نگه می‌دارد. مدیر از آن استفاده نمی‌کند و فقط برای کامل بودن آزمون‌ها لازم است.

```
Add task
```

۵. مطمئن شوید که در تنظیمات مسابقه دست‌کم یکی از زبان‌های زیر فعال است:

```
C++17 / g++
```

## ۸. آزمایش درستی تنظیمات

برای ارسال آزمایشی، یک کاربر آزمایشی بسازید و آن را به مسابقه اضافه کنید، سپس از صفحه شرکت‌کنندگان وارد شوید و ارسال کنید. مسیر ساخت کاربر:

```
Users  ->  Create new user...
```

مسیر افزودن کاربر به مسابقه:

```
Contests -> (your contest) -> Users -> Add user
```

راه‌حل‌ها در این پوشه هستند:

```
jigsaw/solution/
```

امتیاز مورد انتظار هر ارسال (این اعداد با ابزار آماده‌سازی تأیید شده‌اند):

```
model.cpp         100   (۰ + ۱۰ + ۱۵ + ۲۰ + ۲۵ + ۳۰)
odd.cpp            60   (زیرمسئله‌های ۲ و ۳ و ۴)
cover.cpp          35   (زیرمسئله‌های ۲ و ۳)
wa_guess.cpp       25   (فقط زیرمسئله ۴)
greedy.cpp         15   (فقط زیرمسئله ۲)
brute.cpp          10   (فقط زیرمسئله ۱)
tle_n4.cpp         10   (فقط زیرمسئله ۱؛ بقیه با پیام اتمام زمان)
wa_offbyone.cpp     0
wa_infirst.cpp      0
```

دست‌کم این چهار ارسال را آزمایش کنید:

```
model.cpp  odd.cpp  greedy.cpp  tle_n4.cpp
```

اگر نتیجه راه‌حل اصلی کمتر از ۱۰۰ بود، بخش بعد را ببینید. زمان اجرای راه‌حل اصلی روی هر آزمون باید کمتر از نیم ثانیه باشد.

## ۹. رفع اشکال

### الف) خطای اجرای مدیر

اگر در جزئیات ارسال در پنل مدیریت یکی از پیام‌های زیر را دیدید:

```
Execution failed
Evaluation failed
Sandbox error
```

معمولاً یکی از این علت‌ها در کار است:

۱. نام فایل مدیر دقیقاً این نیست:

```
manager
```

در صفحه مجموعه داده، فایل اشتباه را با دکمه زیر حذف کنید و دوباره با نام درست بارگذاری کنید:

```
Delete
```

۲. به‌جای فایل اجرایی، کد منبع بارگذاری شده است. فقط فایل زیر را بارگذاری کنید:

```
cms_upload/manager
```

۳. فایل اجرایی خراب شده است (مثلاً هنگام انتقال با حالت متنی). اندازه درست آن حدود ۲٫۳ مگابایت است. دوباره آن را از مخزن بردارید و بارگذاری کنید.

۴. نوع مسئله به‌اشتباه روی گزینه زیر مانده است و سامانه دنبال بررسی‌کننده می‌گردد:

```
Batch
```

آن را به این گزینه تغییر دهید:

```
Communication
```

پس از هر اصلاح، ارسال‌ها را دوباره داوری کنید. در صفحه مسئله یا صفحه ارسال از این دکمه استفاده کنید:

```
Reevaluate
```

یا

```
Recompile / Re-evaluate all submissions
```

### ب) امتیاز صفر با وجود پاسخ درست

اگر راه‌حل اصلی در همه آزمون‌ها پیام درستی گرفته ولی امتیاز کل صفر است، عبارت‌های منظم امتیازدهی با نام آزمون‌ها جور نیستند. بررسی کنید:

۱. پارامترها دقیقاً همین متن باشند و علامت‌های نقل‌قول از نوع ساده انگلیسی باشند، نه نقل‌قول خمیده:

```
[[0, "^00-[0-9]+$"], [10, "^01-[0-9]+$"], [15, "^02-[0-9]+$"], [20, "^03-[0-9]+$"], [25, "^04-[0-9]+$"], [30, "^0[0145]-[0-9]+$"]]
```

۲. نام آزمون‌ها در فهرست آزمون‌ها به شکل زیر باشد؛ اگر پسوند هم در نام آمده، الگوهای بارگذاری اشتباه بوده‌اند:

```
02-07        درست
02-07.in     نادرست
```

۳. نوع امتیازدهی باید این باشد و نه نوع جمعی:

```
GroupMin
```

۴. اگر شرکت‌کننده امتیاز را صفر می‌بیند ولی در پنل مدیریت امتیاز درست است، آزمون‌ها عمومی نشده‌اند؛ در فهرست آزمون‌ها گزینه زیر را برای همه علامت بزنید و ذخیره کنید:

```
Public
```

برای بررسی عبارت‌ها روی رایانه خودتان (اختیاری) این دستور آماده است:

```
python3 jigsaw/tools/verify_regex.py jigsaw/cms_upload/tests.zip jigsaw/cms_upload/score_type.txt
```

### ج) اشتباه در واحد حافظه

در نسخه‌های ۱.۴ و ۱.۵ واحد این فیلد مگابایت است:

```
Memory limit
```

اگر به‌جای مقدار زیر

```
256
```

عددی مانند مقدار زیر (بایت) نوشته شود، محدودیت بسیار بزرگ می‌شود؛ و اگر عددی بسیار کوچک مانند مقدار زیر نوشته شود، همه ارسال‌ها حتی راه‌حل اصلی با خطای حافظه یا خطای اجرا رد می‌شوند:

```
268435456
0.25
```

مقدار را اصلاح و ذخیره کنید و سپس دوباره داوری کنید. در صورت تردید درباره واحد، متن کنار فیلد در پنل را بخوانید.

### د) ناهماهنگی نام‌ها در پرونده فشرده

اگر پس از بارگذاری تعداد آزمون‌ها کمتر از ۶۴ بود یا پیام خطا گرفتید:

۱. الگوها باید دقیقاً این دو باشند (ستاره جای نام آزمون است):

```
*.in
*.out
```

۲. پرونده فشرده نباید پوشه داخلی داشته باشد. اگر آن را دوباره ساخته‌اید، فایل‌ها باید مستقیماً در ریشه پرونده باشند. ساخت دوباره روی رایانه خودتان:

```
cd jigsaw && bash tools/build_cms_package.sh
```

۳. برای هر ورودی باید خروجی هم‌نام وجود داشته باشد، مثلاً:

```
05-10.in
05-10.out
```

۴. اگر آزمون‌های قدیمی با نام‌های دیگر مانده‌اند، آن‌ها را از فهرست آزمون‌ها حذف کنید و بارگذاری را با گزینه زیر تکرار کنید:

```
Overwrite
```

### هـ) گزینه‌های ورودی و خروجی در نوع مسئله دیده نمی‌شود

اگر پس از انتخاب نوع مسئله، فیلدهای زیر در پنل وجود ندارند:

```
Compilation
User I/O
```

نسخه سامانه قدیمی است (پیش از ۱.۴) و این مسئله در آن نسخه به‌همین شکل قابل اجرا نیست. در این حالت از مدیر سامانه بخواهید نسخه را به‌روزرسانی کند.

### و) همه ارسال‌ها با اتمام زمان رد می‌شوند

اگر حتی راه‌حل اصلی پیام اتمام زمان گرفت، احتمالاً گزینه زیر به‌اشتباه روی حالت دیگری است:

```
User I/O:  std_io
```

در حالت دیگر، برنامه شرکت‌کننده هرگز داده‌ای از مدیر دریافت نمی‌کند و تا پایان زمان منتظر می‌ماند. آن را اصلاح و دوباره داوری کنید.
